These are NSF's rules, not ours. Each one is taken from the Content Instructions NSF publishes on the Research.gov page where that document is uploaded — the PAPPG already distilled by NSF into the handful of rules each section is actually checked against. Every rule below shows NSF's own sentence so it can be verified against the source.
How to read the tags. code means the app decides it with no AI involved — the check is a yes/no fact about the text. reviewer means a model judges it and must quote your draft to support what it says. advisory means the rule is conditional in NSF's own wording, so it is reported but never counted against you.

the PAPPG14 rules

Project Summary

Overview, Intellectual Merit and Broader Impacts each on their own linecode
“Your file must include three separate section headers: Overview, Intellectual Merit, and Broader Impacts. To be valid, a heading must be on its own line with no other text on that line.”NSF — https://www.nsf.gov/policies/pappg

NSF returns a Project Summary without these three headings without review.

The Overview describes the objectives and the methodsreviewer

Derived from NSF's requirement that the Project Summary carry a separate Overview section header — this row checks that something substantive sits under it. NSF's own wording is in the PAPPG.

A heading with nothing substantive under it reads to a reviewer as no answer at all.

The Intellectual Merit statement addresses intellectual meritreviewer

Derived from NSF's requirement that the Project Summary carry a separate Intellectual Merit section header — this row checks that something substantive sits under it. NSF's own wording is in the PAPPG.

This is one of NSF's two review criteria; a reviewer looks for it here first.

The Broader Impacts statement addresses broader impactsreviewer

Derived from NSF's requirement that the Project Summary carry a separate Broader Impacts section header — this row checks that something substantive sits under it. NSF's own wording is in the PAPPG.

This is NSF's second review criterion and the one most often left thin.

Project Summary fits on one pagecode
“File cannot exceed one page.”NSF — https://www.nsf.gov/policies/pappg

An over-length Project Summary is returned without review.

Project Description

A separate Broader Impacts header on its own linecode
“Your file must include a separate section header for Broader Impacts. To be valid, a heading must be on its own line with no other text on that line.”NSF — https://www.nsf.gov/policies/pappg

NSF requires Broader Impacts to be separately labeled, not woven into the narrative.

No hyperlinks in the Project Descriptioncode
“Hyperlinks (URLs) must not be used in the Project Description.”NSF — https://www.nsf.gov/policies/pappg

A reviewer is not permitted to follow them, so anything behind one is unread.

Project Description within its page limitcode
“Refer to your funding opportunity for page limit guidance. The system will enforce the page limit requirements listed in the funding opportunity. If the funding opportunity does not provide a specific limit, the 15-page limit stated in the PAPPG should be followed.”NSF — https://www.nsf.gov/policies/pappg

Most funders return an over-length section without review.

References Cited

Citations follow accepted scholarly practicereviewer
“Follow accepted scholarly practices in providing citations for source materials.”NSF — https://www.nsf.gov/policies/pappg

An incomplete reference list reads as carelessness to a reviewer in your field.

Avoid 'et al.' in the reference listcode advisory
“References should avoid the use of et al. (except for large consortia papers).”NSF — https://www.nsf.gov/policies/pappg

NSF asks for full author lists so reviewers can see who is involved.

Facilities, Equipment and Other Resources

No dollar figures in Facilities, Equipment and Other Resourcescode
“The section must not include any quantifiable financial information.”NSF — https://www.nsf.gov/policies/pappg

Cost information belongs in the budget; NSF treats it as an error here.

Written as a narrativereviewer
“This section should be narrative in nature and include internal and external resources (both physical and personnel).”NSF — https://www.nsf.gov/policies/pappg

A bare equipment list does not tell a reviewer the project is feasible.

Covers internal and external resources, physical and personnelreviewer
“This section should be narrative in nature and include internal and external resources (both physical and personnel).”NSF — https://www.nsf.gov/policies/pappg

Reviewers assess feasibility from this section; omissions read as gaps.

Names senior/key personnel and postdocs drawing no fundsreviewer
“This section should include any senior/key personnel or postdoctoral scholars for whom no funds are being requested in the budget.”NSF — https://www.nsf.gov/policies/pappg

It is the only place an unfunded contributor is visible to a reviewer.

What this does NOT cover. Only these sections are checked against the PAPPG: Project Summary, Project Description, References Cited, Facilities, Equipment and Other Resources. The PAPPG governs much more — biographical sketches, current and pending support, the budget justification, data management plans. Those are reported as not checked here rather than passed. Rules that belong to your specific solicitation are read from that document separately and checked alongside these.
